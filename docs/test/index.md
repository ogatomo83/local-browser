# 開発チーム ドキュメントポータル

ここは開発チームが日々参照する文書の入口です。手順書、設計の記録、議事録、よくある質問などをまとめています。
探しものが見つからないときは、画面上部の検索欄にキーワードを入れてみてください。文書の本文まで全文検索できます。

## はじめての方へ

入社したばかりの方や、ほかのチームから異動してきた方は、まず次の順番で読んでください。

1. [入社初日にやること](onboarding/getting-started.md) — アカウントの準備と開発環境の構築
2. [VPN の設定](onboarding/vpn.md) — 社外から作業するときに必要です
3. [システム構成](architecture/overview.md) — サービス全体の見取り図
4. [用語集](glossary.markdown) — 社内でよく使う略語の意味

一通り読み終えたら、メンターと 30 分ほど時間をとって、分からなかったところを質問してください。
文書が古くなっている箇所を見つけたら、その場で直してもらえると助かります。

## 文書を書くときの決まり

- 形式は原則として Markdown にします。表や図が多い場合に限り HTML も使ってかまいません。
- ファイル名は英小文字とハイフンで付けます。議事録だけは日付で始めます。
- 1 つの文書には 1 つのテーマだけを書きます。長くなったら分けて、相互にリンクしてください。
- 見出しは「##」から始め、「#」は文書のタイトルにだけ使います。
- 手順書には、作業の前提条件と、失敗したときの戻し方を必ず書きます。
- 個人情報、パスワード、API キーは絶対に書かないでください。
