# 入社初日にやること

ようこそ。この文書では、入社初日から 1 週間のうちに済ませておくことをまとめています。
すべてを初日に終える必要はありません。分からないところはメンターに遠慮なく聞いてください。

## 初日の流れ

| 時間 | 内容 | 担当 |
|---|---|---|
| 10:00 | 入社手続き、PC の受け取り | 総務 |
| 11:00 | アカウントの準備 | 情報システム |
| 13:00 | チームの紹介、メンターとの顔合わせ | チームリーダー |
| 14:00 | 開発環境の構築 | 本人 (メンターが補助) |
| 17:00 | 1 日の振り返り | メンター |

## アカウントの準備

次のアカウントは初日の午前中に招待が届きます。届いていない場合は情報システムの #it-help チャンネルに連絡してください。

1. GitHub の組織への招待を受ける。二段階認証は必須です。
2. Slack に参加し、#dev-general と #dev-docs と自分のチームのチャンネルに入る。
3. Google Workspace のカレンダーで、チームの定例会議の予定が入っているか確かめる。
4. VPN の設定をする。手順は [VPN の設定](vpn.md) を見てください。
5. パスワード管理ツールに登録し、共有の保管庫に招待してもらう。

パスワードは必ずパスワード管理ツールに保存し、メモ帳やチャットに貼らないでください。

## 開発環境の構築

PC は macOS を前提にしています。まずパッケージ管理ツールを入れ、そのあと必要なツールをまとめて入れます。

```sh
# 必要なツールを入れる
brew install rustup sqlite git gh
rustup-init -y
rustup target add wasm32-wasip2

# リポジトリを取得する
gh auth login
gh repo clone example/app
cd app
make setup
```

ローカルの DB は Docker で立ち上げます。Docker Desktop を入れてから、リポジトリの直下で `docker compose up -d db` を実行してください。
初回はイメージの取得に数分かかります。立ち上がったら `make migrate` で表を作り、`make seed` でテスト用のデータを入れます。

### よくあるつまずき

- `make setup` が権限エラーで止まる場合は、`/usr/local` の所有者を確認してください。
- Docker の起動が遅い場合は、Docker Desktop の設定で割り当てメモリを 4GB 以上にしてください。
- 社内のパッケージ置き場に接続できない場合は、VPN がつながっているかを確認してください。

## 最初の 1 週間

| 日 | やること |
|---|---|
| 1 日目 | アカウントと開発環境の準備 |
| 2 日目 | [システム構成](../architecture/overview.md) を読み、メンターと一緒にローカルでアプリを動かす |
| 3 日目 | 小さな修正 (文言の変更など) を 1 つ担当し、プルリクエストを出す |
| 4 日目 | コードレビューを受け、指摘を直して merge する |
| 5 日目 | ステージングへのデプロイを見学する。手順は [デプロイ手順](../runbooks/deploy.md) |

最初のプルリクエストは小さくて構いません。レビューの流れに慣れることが目的です。

- 用語が分からないときは [用語集](../glossary.markdown) を見てください。
