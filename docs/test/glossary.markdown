# 用語集

社内の会話や文書でよく出てくる略語と用語をまとめています。五十音順ではなく、分野ごとに並べています。
載っていない用語を見つけたら、追記してください。

## 開発の進め方

**ADR**
: Architecture Decision Record の略。設計上の判断と、その理由を残す文書。後から「なぜこうなっているのか」を調べるときに使う。例は [ADR-001](architecture/adr-001-database.md)。

**PR**
: プルリクエストの略。コードの変更をレビューしてもらうための依頼。

**LGTM**
: 「問題ないと思います」という意味の承認の言葉。レビューで使う。

**ステージング**
: 本番とほぼ同じ構成の検証用環境。本番に出す前にここで動作を確かめる。

## 運用

**SLO**
: サービスが守るべき品質の目標。例えば「1 か月の可用性 99.9%」。

**SLI**
: SLO を測るための指標。成功したリクエストの割合や、応答時間など。

**エラーバジェット**
: SLO から逆算した、許される失敗の量。使い切ったら新機能のリリースを止め、安定化に集中する。

**オンコール**
: 勤務時間外の障害に備えて待機する当番。詳しくは [障害対応フロー](runbooks/incident.html)。

**ポストモーテム**
: 障害のあとに書く振り返りの文書。誰かを責めるためではなく、再発を防ぐために書く。

**ロールバック**
: リリースした変更を取り消し、一つ前の状態に戻すこと。

## 検索

**全文検索**
: 文書の本文に含まれる語で探す方法。このポータルの検索もこれを使っている。

**ベクトル検索**
: 文の意味を数値の並びにして、意味の近い文書を探す方法。言い回しが違っても見つけられる。

**RRF**
: Reciprocal Rank Fusion の略。複数の検索方法の結果を、順位をもとに一つにまとめる手法。

**埋め込み**
: 文を数値の並び (ベクトル) に変換すること。また、その結果。

## 短い略語

社内では 2 文字の略語もよく使います。検索するときに見つかるかどうかの確認にも使っています。

- **DB**: データベース
- **UI**: 画面などの利用者が触れる部分
- **CI**: 変更のたびに自動でテストやビルドを行う仕組み
- **QA**: 品質保証。リリース前の確認作業
