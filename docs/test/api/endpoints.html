API エンドポイント一覧

公開している API の一覧です。すべての API は /v1 から始まり、応答は JSON で返します。 認証が必要な API には、ヘッダに Bearer トークンを付けてください。詳しくは 認証方式 を見てください。

利用者

メソッドパス説明認証
GET/v1/users利用者の一覧を返す。名前やメールアドレスで絞り込める必要
POST/v1/users利用者を新しく登録する必要 (管理者)
GET/v1/users/{id}利用者 1 人の情報を返す必要
PATCH/v1/users/{id}利用者の情報を一部更新する必要 (本人か管理者)
DELETE/v1/users/{id}利用者を退会扱いにする。データはすぐには消さない必要 (管理者)

商品

メソッドパス説明認証
GET/v1/products商品の一覧を返す。分類や価格の範囲で絞り込める不要
GET/v1/products/{id}商品 1 件の詳細を返す不要
GET/v1/products/search商品名と説明文を全文検索する不要

注文

メソッドパス説明認証
POST/v1/orders注文を作る。在庫が足りない場合は 409 を返す必要
GET/v1/orders/{id}注文 1 件の状態を返す必要 (本人か管理者)
POST/v1/orders/{id}/cancel注文を取り消す。発送後は取り消せない必要 (本人か管理者)

エラーの返し方

エラーのときは、次の形の JSON を返します。code は機械が判断するための値、message は人が読むための説明です。

{
  "code": "out_of_stock",
  "message": "在庫が足りません",
  "request_id": "01JC8Z..."
}
状態コード意味
400入力の値が正しくない
401認証されていない、またはトークンの期限が切れている
403権限がない
404対象が見つからない
409状態が合わない (在庫切れ、二重の登録など)
429呼び出しが多すぎる。1 分あたり 600 回まで

API を追加・変更するときの決まり

  • 既存の API の応答から項目を消したり、意味を変えたりしない。必要なら /v2 を作る。
  • 項目の追加は自由にしてよい。呼び出す側は、知らない項目を無視するように作る。
  • この一覧を更新してから、プルリクエストを出す。
